# Decisions

Record applicable durable, surprising, or hard-to-reverse decisions as
append-only ADRs when a real trade-off means future maintainers need to know why
the decision was made.

Use a stable name such as `ADR-0001-short-title.md`. When a decision changes, add a new ADR that identifies the decision it supersedes; do not erase the earlier record.

Each ADR should record its status and date, context, decision, real alternatives
considered, consequences, applicable compatibility or migration constraints,
and verification approach. Do not create an ADR for routine implementation
details without a durable trade-off.

ADRs preserve decision rationale and history. `ARCHITECTURE.md` separately
describes the resulting current system structure. When a new decision changes
that structure, update both views.
